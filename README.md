## О проекте

**Hismar Check** — внутренний инструмент производства для ведения документации по системе НАССР.
Сотрудник открывает приложение на телефоне (или сканирует QR-код на рабочем месте), выбирает нужный журнал
и заполняет Google Форму. Ответы попадают в Google Таблицы, а приложение умеет эти таблицы
красиво показывать: с поиском, сортировкой и пагинацией.

Проект — это **статический сайт** (чистые HTML/CSS/JS, без сборки и фреймворков), который использует:

- **Google Forms / Google Sheets** — как хранилище и ввод данных;
- **Google Sheets API v4** — для чтения таблиц прямо из браузера;
- **Google Apps Script (Web App)** — как серверную часть: авторизация, заявки СГИ, опрос датчиков Tuya.

## Возможности

- 📚 **Каталог журналов и чек-листов** с поиском, фильтрацией по категориям (мультивыбор) и избранным.
- ✏️ **Быстрое заполнение** — кнопка открывает форму; для многих журналов используется **предзаполненная ссылка**
  (ответы «Да» уже проставлены, нужно изменить только отклонения).
- 📖 **Просмотр журнала** — данные из Google Таблицы: сортировка по любому столбцу, поиск по всем полям,
  пагинация (25 / 50 / 100), автоопределение столбца с датой и сортировка «новые сверху».
- 📷 **Сканер QR-кодов** — встроенный (через `BarcodeDetector` с запасным вариантом на `jsQR`).
- ⭐ **Избранное** — хранится на устройстве (`localStorage`).
- 🛠️ **Заявки для СГИ** — создание заявок (в т. ч. с фото), смена статусов, фильтры по статусу и периоду,
  изменяемая ширина столбцов, автообновление.
- 🌡️ **Датчики** — показания температуры и влажности, подсветка отклонений от нормы и низкого заряда батареи,
  запрос свежих данных «по кнопке».
- 📊 **Мастер-таблица** (для администраторов) — все журналы со ссылками на таблицу, форму, редактор формы и
  скачиваемые QR-коды.
- 👥 **Пользователи системы** (для администраторов) — список сотрудников из таблицы доступа.
- 🔐 **Вход по ФИО и пинкоду** с подсказками ФИО, защитой от перебора и разграничением доступа к журналам.
- 📱 **PWA** — устанавливается на домашний экран, работает офлайн в части кэшированных страниц.

## Технологии и архитектура

```
┌──────────────────────────────┐
│  Браузер / PWA (этот репо)   │
│  HTML + CSS + vanilla JS     │
└───────┬───────────┬──────────┘
        │           │
        │ чтение    │ POST (JSON, text/plain)
        ▼           ▼
┌──────────────┐  ┌──────────────────────────────────────┐
│ Google       │  │ Google Apps Script (Web App)         │
│ Sheets API   │  │  • авторизация и пользователи        │
│ v4 (API key) │  │  • заявки СГИ (статусы, фото)        │
└──────┬───────┘  │  • опрос датчиков Tuya → таблица     │
       │          └──────────────────┬───────────────────┘
       ▼                             ▼
┌──────────────────────────────────────────────┐
│ Google Таблицы / Формы / Drive (QR-коды, фото)│
└──────────────────────────────────────────────┘
```

- **Фронтенд:** vanilla JS, шрифт [Manrope](https://fonts.google.com/specimen/Manrope), собственная дизайн-система на CSS-переменных.
- **Бэкенд:** три независимых Apps Script Web App (авторизация, СГИ, датчики) — запросы отправляются как
  `POST` с `Content-Type: text/plain;charset=utf-8`, чтобы обойтись без CORS-preflight.
- **Кэш:** Service Worker (`sw.js`) — `journals.json` по стратегии *network-first*, остальное — *cache-first*.

## Авторизация и роли

1. Пользователь вводит ФИО и 4-значный пинкод на `login.html`.
2. Apps Script проверяет данные по таблице «Пользователи» и возвращает **токен**, срок его действия,
   тип пользователя (`type`), должность (`position`) и список разрешённых журналов (`allowed`).
3. Сессия сохраняется в `localStorage` под ключом `gcheck_auth`.
4. `auth-guard.js` на каждой защищённой странице:
   - перенаправляет на `login.html`, если токена нет или он истёк;
   - раз в 10 минут в фоне сверяется с сервером (`verify`) — если пользователя отключили или сменили пинкод,
     выполняется выход;
   - при отсутствии сети пользователь остаётся в системе (работа в PWA/офлайн);
   - публикует данные пользователя в `window.gcheckUser` и событие `gcheck:user` при их обновлении.

**Роли:**

| Параметр | Значение | Что даёт |
|---|---|---|
| `type` | `Администратор` | Мастер-таблица, датчики, пользователи, ссылка на таблицу заявок СГИ |
| `position` | `Сотрудник СГИ` | Автообновление и ссылка на таблицу в разделе заявок |
| `allowed` | `"*"` или массив ID журналов | Список видимых журналов |

**Действия Apps Script авторизации:** `warmup`, `suggest`, `login`, `verify`, `listUsers`.

## Каталог журналов (`journals.json`)

Каталог — это массив объектов. Именно из него строятся главная страница, просмотр журналов и мастер-таблица.

```jsonc
{
  "id": "НАССР-Ж-04",                       // уникальный код: Ж — журнал, Ч — чек-лист
  "name": "НАССР-Ж-04 Контроль стекла и пластика коридора чистой зоны 2 этажа",
  "tags": ["Включения"],                    // категории (см. ниже)
  "sheetId": "…",                           // ID Google Таблицы с ответами
  "sheetName": "Ответы на форму (1)",       // название листа
  "sheetUrl": "https://docs.google.com/spreadsheets/…",
  "formUrl": "https://docs.google.com/forms/…/viewform",   // пустая форма
  "formUrlEdit": "https://docs.google.com/forms/…/edit",   // редактор формы
  "qrDriveId": "…",                         // файл QR (пустая форма) в Google Drive
  "formUrlPrefill": "…?usp=pp_url&entry.123=Да…",          // предзаполненная форма (необязательно)
  "qrPrefillDriveId": "…"                   // QR предзаполненной формы (необязательно)
}
```

**Правила:**

- `name` должен начинаться с `id` — по этому префиксу интерфейс отделяет код от названия.
- Если задан `formUrlPrefill`, кнопка «Заполнить» ведёт на него, иначе — на `formUrl`.
- Если ни одной ссылки на форму нет, кнопка отображается неактивной («форма не подключена»).
- Для форм на Apps Script `formUrl` заканчивается на `/exec`.
- Допустимые категории (порядок задаётся в `TAG_ORDER` в `index.html`):
  `Санитария`, `АХО`, `Оборудование`, `Продукт`, `Включения`, `Температурные`, `Вредители`, `Учёт`, `Прочее`.
  Написание «Учет» автоматически нормализуется в «Учёт».
- Журнал можно скрыть у конкретного пользователя, не включая его ID в `allowed`.

### Как добавить новый журнал

1. Создайте Google Форму и привяжите к ней таблицу ответов; дайте таблице доступ «по ссылке — Читатель».
2. Сгенерируйте QR-код на форму и загрузите его в Google Drive — понадобится ID файла.
3. *(Опционально)* получите предзаполненную ссылку: «Получить предварительно заполненную ссылку» в редакторе формы.
4. Добавьте объект в `journals.json` по образцу выше.
5. Выдайте доступ нужным пользователям (`allowed`) в таблице пользователей.
6. Увеличьте версию кэша в `sw.js` (см. [Деплой](#деплой-и-обновление-версии)).

## Заявки для СГИ

Раздел для заявок на ремонт и обслуживание оборудования.

**Создание заявки** — через форму на странице или через Telegram-бота. Поля: краткое описание, участок,
тип оборудования, оборудование, фото (необязательно). Фото сжимается на клиенте (до 1000 px по длинной стороне,
JPEG, качество 0.65) и догружается в фоне отдельным запросом с тремя попытками.

**Статусы и разрешённые переходы** (должны совпадать с `ALLOWED_TRANSITIONS` в Apps Script):

```
Открыта ⇄ В работе → Выполнена
                   → Выполнена. Проведена мойка и дезинфекция
Выполнена / Выполнена. Проведена мойка и дезинфекция → В работе
```

**Таблица:** подсветка строк по статусу, сортировка, поиск, фильтры (мультивыбор статусов со счётчиками;
«Сегодня / Вчера / Период»), изменяемая ширина столбцов (сохраняется в `localStorage`, двойной клик — сброс),
просмотр фото в модальном окне.

**Действия Apps Script СГИ:** `createRequest`, `attachPhoto`, `setStatus`.

## Датчики

Страница `sensors.html` показывает данные из таблицы «Показания датчиков (реальные)».

- Фильтры: датчик, период (все даты / сегодня / вчера / произвольный), «только отклонения».
- Подсветка: температура или влажность вне допустимого диапазона (формат диапазона, например `2...6`) и заряд батареи ниже 30 %.
- Кнопка **«Получить данные сейчас»** вызывает действие `logTuyaData` — скрипт опрашивает датчики Tuya и
  дописывает показания в таблицу.
- Пагинация: 50 / 100 / 200 записей.

## Настройка и запуск

Сборка не нужна — это обычные статические файлы.

### Локально

Service Worker и камера требуют `https` или `localhost`, поэтому запускайте через локальный сервер:

```bash
# любой статический сервер, например:
python3 -m http.server 8080
# → http://localhost:8080/login.html
```

### Что нужно настроить

| Что | Где | Описание |
|---|---|---|
| `API_KEY` | `journal.html`, `sgi.html`, `sensors.html` | Ключ Google Sheets API. Ограничьте его по HTTP-referrer и только на Sheets API |
| `APPS_SCRIPT_URL` | `login.html`, `auth-guard.js`, `users.html` | URL Web App авторизации (оканчивается на `/exec`) |
| `APPS_SCRIPT_URL`, `SHEET_ID`, `SHEET_NAME` | `sgi.html` | Web App и таблица заявок СГИ |
| `SENSORS_SCRIPT_URL`, `SHEET_ID`, `SHEET_NAME`, `DEVICES` | `sensors.html` | Web App датчиков, таблица показаний и список расположений |
| `AREAS`, `EQUIPMENT_TYPES` | `sgi.html` | Справочники для формы заявки (типы оборудования должны совпадать со скриптом) |
| Таблицы | Google Sheets | Доступ «по ссылке — Читатель» для всех таблиц, которые читаются через API |

Подключение внешних Google-сервисов: Apps Script публикуются как *Web App* с доступом «Все», а проверка
прав выполняется внутри скрипта по токену.

## Деплой и обновление версии

Подойдёт любой статический хостинг с HTTPS (GitHub Pages, Cloudflare Pages, Netlify и т. п.).

В `sw.js` задаётся имя кэша:

```js
const CACHE_NAME = 'nassr-journals-v121026_12';
```

**При каждом значимом деплое меняйте это значение** — Service Worker скачает новые файлы,
а старые версии кэша удалятся автоматически. Без этого у пользователей может «залипнуть» старая версия страниц.
Исключение — `journals.json`: он загружается *network-first*, поэтому правки каталога подхватываются сразу при наличии сети.

> Страницы `*.html`, `*.js` кэшируются по стратегии *cache-first* — обновление версии кэша обязательно.

## Безопасность и ограничения

Приложение рассчитано на **внутреннее использование** и сознательно простое. Учитывайте:

- **Проверка в браузере — это удобство, а не защита.** Скрытие страниц и журналов по ролям выполняется на клиенте.
  Реальная проверка токена должна происходить в Apps Script (так и сделано для `listUsers`, `logTuyaData` и т. д.).
- **Таблицы с ответами читаются по ссылке.** Данные журналов доступны всем, у кого есть ссылка на таблицу и ID;
  не храните в них конфиденциальную информацию.
- **API-ключ Google виден в клиентском коде** — обязательно ограничьте его по HTTP-referrer и по API (только Sheets API).
- **Пинкоды** в таблице пользователей хранятся и отображаются администратору в открытом виде (`users.html`).
  Используйте уникальные пинкоды, не совпадающие с личными.
- **Блокировка перебора** пинкода реализована на сервере (`locked` + `retryAfterSec`).
- **Избранное и настройки таблиц** (`localStorage`) привязаны к устройству и не синхронизируются.
- Сканер QR требует доступ к камере и работает только по `https`/`localhost`.
