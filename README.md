# Журналы НАССР — itle kitchen

Веб-каталог журналов и чек-листов НАССР (HACCP) для отдела контроля качества. Заменяет бумажные журналы и разрозненные ссылки на Google Формы одним удобным сайтом: сотрудники заполняют данные по QR-коду, руководители просматривают и анализируют записи в едином интерфейсе.

## Зачем это нужно

Раньше каждый журнал существовал как отдельная Google Таблица со своей формой и своим QR-кодом — при 90+ журналах и чек-листах найти нужный документ, особенно с телефона в цеху, было неудобно. Этот проект решает три задачи:

1. **Быстрый доступ для сотрудников.** Один QR-код на входе в цех → каталог со всеми журналами → поиск и фильтр по категориям → нужная форма открывается за пару кликов.
2. **Единый просмотр для руководителей.** Данные каждого журнала отображаются на сайте в удобной таблице (поиск, сортировка по столбцам), без необходимости открывать 90+ отдельных Google Таблиц.
3. **Порядок в инфраструктуре.** Все ссылки, ID таблиц и форм собраны в одной мастер-таблице, а не разбросаны по переписке и памяти.

## Возможности

- 🔍 **Поиск и фильтрация** по названию журнала и по тегам категорий (Санитария, АХО, Оборудование, Продукт, Включения, Температурные, Вредители, Учёт, Прочее), с поддержкой множественного выбора тегов (пересечение — «И»).
- 📊 **Просмотр данных журнала** прямо на сайте — таблица с сортировкой по клику на заголовок столбца (с корректной сортировкой дат в формате `дд.мм.гггг чч:мм:сс`) и поиском по всем столбцам.
- 📋 **Мастер-таблица** — отдельная страница со сводным списком всех журналов и кликабельными ссылками на таблицы, формы и их редактирование.
- 📱 **PWA** — сайт можно установить на телефон как приложение (иконка на главном экране, офлайн-доступ к списку журналов через service worker).
- 🔒 **Простой пароль на главной странице** — ограничивает доступ к каталогу от случайных людей (не является полноценной защитой данных; доступ к самим таблицам разграничен отдельно на уровне Google).
- 💾 **Резервное копирование** — скрипт на Google Apps Script, который по запросу копирует все таблицы и формы в структурированный бэкап на Google Диске.

## Структура проекта

```
├── index.html          # Главная страница: поиск, фильтр по тегам, список журналов
├── journal.html         # Страница одного журнала: таблица данных из Google Sheets API
├── master.html           # Мастер-таблица: сводный список со ссылками на таблицы/формы
├── journals.json         # Данные по всем журналам (источник истины для сайта)
├── manifest.json          # PWA-манифест (название, иконки, цвета)
├── sw.js                   # Service worker для офлайн-кэширования
├── icon-192.png            # Иконка приложения 192×192
├── icon-512.png             # Иконка приложения 512×512
├── icon-512-maskable.png     # Maskable-иконка для Android
└── backup_forms.gs            # Apps Script для резервного копирования (запускается из мастер-таблицы)
```

## Как это работает

1. Данные каждого журнала хранятся в отдельной Google Таблице, заполняемой через связанную Google Форму (сканирование QR-кода → форма → новая строка в таблице).
2. Все таблицы, формы и метаданные описаны в `journals.json` — единый файл с записями вида:
   ```json
   {
     "id": "НАССР-Ж-01",
     "name": "НАССР-Ж-01 Журнал учета пищевых добавок",
     "tags": ["Учет"],
     "sheetId": "...",
     "sheetName": "Ответы на форму (1)",
     "sheetUrl": "...",
     "formUrl": "...",
     "formUrlEdit": "...",
     "qrDriveId": "...",
     "formUrlPrefill": "...",
     "qrPrefillDriveId": "..."
   }
   ```
3. `index.html` и `master.html` читают `journals.json` напрямую. `journal.html` дополнительно обращается к **Google Sheets API** (по `sheetId`/`sheetName` конкретного журнала), чтобы показать актуальные данные таблицы прямо на сайте.
4. Источник данных для `journals.json` — отдельная **мастер-таблица** на Google Диске, которую удобно вести вручную и экспортировать при обновлении структуры.

## Технологии

Чистые HTML/CSS/JavaScript, без сборщиков и фреймворков — сайт целиком статический и размещён на **GitHub Pages**. Для чтения данных таблиц используется **Google Sheets API** (публичный API-ключ, ограниченный по домену и типу API). Резервное копирование реализовано на **Google Apps Script**.

## Настройка и запуск

1. Разместите все файлы репозитория в корне GitHub Pages (Settings → Pages → Deploy from branch).
2. В `journal.html` и `master.html` укажите свой ограниченный API-ключ Google Sheets API (Google Cloud Console → Credentials, с ограничением по домену сайта и по Google Sheets API).
3. Убедитесь, что все Google Таблицы, на которые ссылается `journals.json`, имеют доступ «Все, у кого есть ссылка — Читатель» — иначе API не сможет их прочитать.
4. Заполните пароль в `index.html` (переменная в начале скрипта) для базового ограничения доступа к каталогу.
5. Обновляйте `journals.json` при добавлении новых журналов или изменении ссылок — эффект виден сразу после коммита, без пересборки сайта.

## Резервное копирование

Скрипт `backup_forms.gs` запускается вручную из мастер-таблицы (Расширения → Apps Script → функция `startBackup`). Копирует все таблицы и формы в папку `Журналы <дата>` на Google Диске, создаёт резервную копию мастер-таблицы с перелинковкой на свежие копии, и продолжает работу автоматически, если не укладывается в лимит времени выполнения одного запуска. Подробности — в комментариях внутри самого файла.

## Ограничения

- Это не полноценная система с бэкендом — все данные по-прежнему хранятся в Google Таблицах и Формах, сайт лишь предоставляет удобный слой просмотра и навигации поверх них.
- Пароль на главной странице виден в исходном коде сайта — это фильтр от случайных посетителей, а не средство защиты конфиденциальных данных.
- Редактирование записей журналов происходит через сами Google Формы/Таблицы, не через сайт напрямую.
